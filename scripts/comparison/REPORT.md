## 二、四组策略

- **G1 基线**：现状用法——`analyze_article` 推荐预置主题（tech-minimal / magazine / business）直排原文，无组件。
- **G2 三方向门**：agent 按色彩推导协议直出 3 个温度（安稳/反差/大胆）主题，截图给用户选。vite 选 B（深松绿衬线编辑风），noodle 选 C（深夜蓝黑暗场）。
- **G3 品牌记忆**：品牌档案「墨账 ink-ledger」（钢笔墨蓝+牛皮纸底，色彩论证存档）+ 2 个品牌专属组件（ink-quote 金句卡 / ink-stat 数据条）+ voice/taboos 规则，重排 coffee 文章。
- **G4 品牌迭代**：`brand_learn` 记录反馈（h2 层级弱、数据条字号小）→ 主题 v2（h1 32→34px、h2 24→25px+边框 5→7px）→ 复用档案排 vite 文章。

## 四、过程中抓到的真 Bug（升级的副产品）

1. **canvas 背景色静默失效**（已修复）：`renderCanvas` 里 `bg ?? palette.canvasBg`，但 `prop()` 缺参返回空字符串而非 undefined，`??` 不短路 → 所有未显式传 `bg` 的 canvas 用了空背景色。同函数 `padding` 的注释写了这个坑，`bg` 行自己踩了。**影响**：所有暗色整页主题（canvasBg token）背景全丢，且无任何诊断。修复后 noodle-C 亮度 236→46。
2. **组件模板参数检查**：ink-quote 模板误用 `{{text}}`（正文应走 `{{body}}`），被保存时自检抓出——验证了组件校验闸门有效。
3. **brand_save 的 block 补全**：agent 直出主题只写关键 block 时自动补全 15 项，降低产出门槛（新增 `completeThemeBlocks` 导出）。

## 五、三方向门的价值（截图为人眼评审）

`scripts/comparison/output/shots/` 下每篇文章 3 个方向的全景截图（G2-panorama-*）：

- vite：A 钢蓝灰（稳妥）/ B 深松绿衬线（反差）/ C 黑白粗野+信号橙（大胆）——三种气质真实拉开
- noodle：A 暖棕杂志 / B 宣纸水墨 / C 深夜暗场——选定 C 的理由写入 directions-report.json（形式从内容意象长出来）

对比基线「拿到什么用什么」，三方向把**选择权还给人**，且配比强制包含大胆款，抵消模型偏爱极简的确定性偏差。

## 六、品牌记忆系统的复用证据

1. **建档**：`brand_save` 固化 profile.json + brand.md（含色彩论证、voice、taboos）
2. **复用**：`brand_apply` 一次调用 → 主题 + 2 个专属组件自动同步 → 直接排版
3. **迭代**：`brand_learn` 追加记录 → v2 主题层级比提升 → **第二篇文章自动继承**（G4 vite 与 G3 coffee 视觉同源，色彩档数 52 vs 57，同属墨账纸感系统）
4. **人可改**：brand.md 是 Markdown，用户手改后重新 brand_save 即可，learnings 不丢

## 七、结论：怎么改最能提升排版效果

按提升幅度排序：

1. **品牌记忆系统（最大提升）**：把「每次从零选模板」变成「在自家资产上迭代」。独特性警告从 3/3 消失，跨文章一致性建立，且改进可积累（G4 > G3 > G2 > G1 的品牌对齐度单调递增）。
2. **agent 直出主题 + 色彩推导协议**：rationale 强制论证消灭「默认蓝抽签」；三方向门提供真实选择权。
3. **品牌专属组件**：ink-stat 把 Markdown 表格变成账本行，是「内容形态适配」而非「装饰堆砌」——组件数量少（2 种）但表达力强。
4. **review_article 发布前 gate**：层级比/密度/独特性三项确定性检查 + 眯眼测试框架，在 G3 就拦下了密度偏高问题。
