## 32. 默认 block：所有主题的基线

`packages/theme/src/presets.ts` 的 `defaultBlocks()` 是**所有主题的基线**：
6 套原创预置主题、agent 直出的主题、品牌档案里没写的 block 全部继承它。
所以它长什么样，直接决定「默认排版」好不好看 —— 改它的收益覆盖全部主题，
代价也是全部主题。

### 旧版三个毛病（都是模板感来源，不是审美偏好）

| 症状 | 为什么难看 | 改成 |
| --- | --- | --- |
| h1/h2/h3 全是强调色、字重相同 | 一屏里到处同一种颜色，层级只剩字号；强调色用尽后，链接/加粗再想强调就没有手段 | 标题用正文墨色，层级交给字号 + 字重 + 空气；强调色只留给链接、行内代码、组件 |
| 每个元素的下边距都是同一个 `spacing.block` | 标题和段落一样挤，一页读下来没有呼吸 | 标题的上边距用 em（随字号缩放），h2 给到 1.9em；段落间距仍归 token |
| 引用块是「圆角灰药丸」、行内代码是纯灰块 | 这两样加在一起就是文档模板的脸 | 引用块去掉圆角（左线 3px + 浅底，内部段落间距交给渲染层）；行内代码浅底 + 1px 描边 |

借鉴对象（同类里最稳的三个）：

- **Tailwind Typography 的 `prose`**：层级靠 h1 800 / h2 700 / h3 600 + 大间距，颜色几乎不参与。
- **mdnice 的「默认最佳实践」**：朴素黑字标题；引用块 `border-left: 3px` + 5% 黑底、无圆角。
  它还有一条微信实测值得记住：**纯黑 `#000` 的 `color` 会被编辑器吞掉**（所以正文别设纯黑）。
- **doocs/md 的 default**：h1 用 `display: table` + 下划线让线**贴字**；行内代码浅底 + 1px 描边；
  正文 `letter-spacing` 明显更大（0.1em）。

按中文排版定的两个值：正文字距 **0.04em**（在 doocs 的 0.1em 与 mdnice 的 0 之间取中，
看得出节奏又不吃栏宽）；**加粗不染色**（染色加粗是「满屏主色」的另一半来源）。

### 代价：贴字下划线要求主题显式取消

h2 用 `display: table` 让下划线只贴文字宽度，于是：

- 自带下划线的主题必须写 `border-bottom: none` 才能换成别的装饰（`gov-red` 就是）；
- 居中的主题还要给 `margin: … auto …`（`magazine` 就是）—— `text-align: center`
  只对齐盒子里的字，盒子本身仍是左对齐的收缩宽度。

这是「一个装饰各写一次」换来的，比三级标题全同款划算。

### 修正：代码块里不再嵌第二个盒子

行内代码样式经 `code {}` 生效，而代码块是 `<pre><code>` —— 于是代码块里嵌了第二个盒子
（自己的浅底 + 描边 + 内边距 + 圆角），字号还叠两次（pre 0.86em × code 0.88em ≈ 0.76em）。
表现是「代码块里又套一个小框，字还特别小」。

`compileThemeToCss` 现在在 block 规则后追加一条 `pre code { … }` 重置，**只重置盒模型与字号**，
不动 `color` / `font-family` —— 那两样是主题的表达手段（深色主题故意用亮色代码字），
重置掉就把主题的意思改了。

### 已知缺口：表格没有 block

`BLOCK_NAMES` 里没有 `table` / `th` / `td`，所以 Markdown 表格拿不到任何主题样式，
在预览里就是「一堆没有边框的文字」。白名单其实已经放行了 `border-collapse` / `table-layout`
这类属性，说明当初留了口子。没补的原因是取舍：SKILL 建议数据用 `:::ink-stat` 这类数据条
而不是 Markdown 表格（微信里表格挤）。要补就是 `BLOCK_NAMES` 加三个名字 + 默认样式 + 更新快照。
